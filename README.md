# akatsuki

従業員4人、渋谷区・新宿区の2棟を管理するWebアプリの試作。
利用者向け説明は [はじめに](docs/はじめに.md) を参照。

## 開発

Node.js 22.12以上（検証: 24.19.0）。

```sh
npm ci
npm run dev -- --port 5173
npm test
npm run build
```

開発サーバーを起動した状態で `npm run test:browser` を実行すると、予定・半休申請承認・PDF・既存設備機能・画面幅320〜1920pxをChromiumで検証します。
既定のブラウザは `/usr/bin/chromium`。`CHROMIUM_PATH` で変更可能。`APP_URL` で対象サーバーを変更可能。
画面画像は `/tmp/akatsuki-browser-check`、PDFは `/tmp/akatsuki-leave.pdf` と `/tmp/akatsuki-shifts.pdf` に出力します。

## 実装済みの試作

- ネイビー・ゴシック体、PC・タブレット・スマホ向けレイアウト。
- ホームの今日・今週・今月一覧、カレンダー、予定とタスク、担当者、編集・削除・完了。
- 設備追加、交換履歴、周期変更、交換予定と各種フィルタ。
- 月間シフト、自分の行の編集、全日・午前・午後の有給申請、管理者承認・却下。
- 付与期間・日数の設定、承認済み・申請中・残日数の計算、シフトから有給管理への反映。
- 日本語PDFの直接ダウンロード。書式は暫定。フォントの出典・ライセンスは public/fonts に同梱。

PDF関連の処理はダウンロード時だけ読み込みます。日本語の欠落を防ぐため、静的TTFを全文字埋め込みします。
PDFの文字抽出だけでは描画を保証できないため、変更時はPDFを画像化して目視確認もしてください。

## ログイン・共有保存（2026-11-01追加）

通常の画面はログインを要求します。従来の試作は `?demo=1` で開きます。
開発時は別々のターミナルで `npm run dev:server` と `npm run dev -- --port 5173` を起動してください。
`APP_ORIGIN` の既定値は `http://localhost:5173` です。APIへの更新リクエストはこのOriginに限ります。
静的ファイルとAPIを一緒に配信する場合はビルド後 `npm start` を使い、APP_ORIGINをアクセス先に合わせます。

Better Authによるパスワード認証とCookieセッション、管理者限定の招待リンク、利用停止、会社別アクセス制御、共有SQLite保存、操作記録、同時編集の衝突検出を追加しました。
社員の状態を毎回サーバーで確認します。データの更新は「最新に更新」で読み込みます。
招待は48時間・1回限りで、データベースにはリンクのハッシュだけを保存します。メール自動送信は未接続です。

保存先は `.local/`（Git管理対象外）、変更する場合は `APP_DATA_DIR` を使います。
認証用秘密値と初期管理者登録用コードを初回起動時に非公開ファイルとして生成します。チャットやログに表示しないでください。
初回登録画面のコードは運用担当者が `.local/setup-token` を安全に確認して入力します。開発時の自動検証は一時ディレクトリ内の専用コードと仮アカウントを使います。
本番ではHTTPSの `APP_ORIGIN`、永続ディスク、アクセス制限された秘密値の保管、別媒体への定期バックアップが必要です。無料枠での常時稼働先は未選定です。

検証: `npm test`、ビルド後 `node scripts/check-auth-browser.mjs`（3305番ポートを使用）、起動中の試作に `npm run test:browser`。
`npm run backup` はSQLiteのオンラインバックアップと整合性チェックを行います。同じディスク内のコピーなので、災害対策には別の保管先が必要です。
復元時はサーバーを止め、バックアップを別ディレクトリで検証し、復元DBのsessionテーブルを空にして古いログイン状態を失効させてから切り替えてください。

未対応: 公開URL、メール送信、パスワードを忘れた場合のメール復旧、MFA、Googleドライブ接続、OCR、通知、クラウドへのPDF直接保存。
以前の「認証未実装」という説明はブラウザだけの試作についての記録です。認証・共有保存は現在、開発環境内で検証済みです。本番運用の準備完了を意味しません。

## Obsidian自動同期

`obsidian-plugin/` にMacの「暁」向け専用プラグインがある。`npm run check --prefix obsidian-plugin` と `npm run build --prefix obsidian-plugin` で検証・ビルドする。
管理者画面から端末別の読み取り専用コードを発行し、`/api/obsidian/sync/index` と `/api/obsidian/sync/file` で許可した資料だけを配信する。
配布ZIPは `python scripts/package-obsidian-plugin.py`、引き継ぎ一式は `python scripts/export-handoff.py` で生成する。どちらもGit管理外の `.private-notes/` に置く。

アプリが未公開なのでMac実機への接続は未確認。ChatGPT会話の常時自動取得機能ではない。詳細は `docs/Obsidian自動同期.md` を参照。

## Turso

共有データはlibSQL共通層を使用する。`TURSO_DATABASE_URL` と `TURSO_AUTH_TOKEN` を設定するとTursoへ接続し、未設定の開発環境では `.local/akatsuki.sqlite` を使用する。秘密値はGitHub、Obsidian、チャットへ保存しない。

既存SQLiteから空のTursoへ移す場合は、秘密変数を安全に設定して `npm run migrate:turso` を実行する。移行ツールはローカルの整合性確認とバックアップを行い、移行先が使用中なら停止し、全表の件数と内容ハッシュを照合する。

Turso実環境への接続は未確認。接続前のローカルlibSQL、認証、権限、同時更新は自動テスト済み。
