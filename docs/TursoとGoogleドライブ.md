# TursoとGoogleドライブの保存方針

更新: 2026-11-01（日本時間）

## 決定

無料運用の第一候補を次の構成にする。

- Turso: 社員、権限、予定、設備、交換履歴、シフト、有給、操作記録、領収書の検索項目を保存する。
- Googleドライブ: 領収書原本、作成したPDF、依頼書を保存する。
- GitHub: アプリのソースコードと秘密情報を含まない開発資料を保存する。
- Obsidian「暁」: 専用プラグインで開発資料を読む。業務データやパスワードの保存先にはしない。

無料枠の条件は変更されるため、Tursoの登録画面で容量、休止条件、カード登録の有無を接続直前に確認する。有料プランへの変更は自動で行わない。

## 秘密情報

TursoのデータベースURLと認証トークン、Googleの認証情報はGitHub、Obsidian、チャットへ保存しない。公開先の秘密変数として設定する。

想定する環境変数名:

- `TURSO_DATABASE_URL`
- `TURSO_AUTH_TOKEN`
- `GOOGLE_CLIENT_ID`
- `GOOGLE_CLIENT_SECRET`

値そのものは `.env` やGit管理対象のファイルへ書かない。

## 移行手順

1. 現在のSQLite版で全テストを維持する。
2. Turso用の保存処理を追加し、ローカルの一時データベースで同じ認証・権限テストを実行する。
3. SQLiteからTursoへ一度だけ移すツールを作り、件数と内容のハッシュを照合する。
4. Turso側のバックアップまたはエクスポートと復元を確認する。
5. 公開先の秘密変数へURLとトークンを登録する。
6. 架空データで公開環境を確認してから、実際の社員を招待する。

移行完了まではSQLiteを削除しない。同時に両方へ書き込む期間を長く設けず、切替日時と移行元を記録する。

## Googleドライブ

Googleドライブにはファイル本体を置き、TursoにはGoogleのファイルID、表示名、金額、経費項目、処理状態、内容ハッシュを記録する。同じ領収書の二重登録はファイルIDと内容ハッシュで防ぐ。

最初は個人Googleアカウントで開始できる構造にし、法人用アカウントへ変更するときは、先にファイルを移して権限とIDを確認してから旧接続を解除する。

## 現在の状態

保存先の方針は決定した。アプリ本体はまだSQLiteを使用しており、TursoとGoogle OAuthの実接続は未完了。登録用の秘密値をチャットへ送る必要はない。
