# TursoとGoogleドライブの保存方針

更新: 2026-11-01（日本時間）

## 決定

無料運用の第一候補を次の構成にする。

- Turso: 社員、権限、予定、設備、交換履歴、シフト、有給、操作記録、領収書の検索項目を保存する。
- Googleドライブ: 領収書原本、作成したPDF、依頼書を保存する。
- GitHub: アプリのソースコードと秘密情報を含まない開発資料を保存する。
- Obsidian「暁」: 専用プラグインで開発資料を読む。業務データやパスワードの保存先にはしない。

無料枠の条件は変更されるため、Tursoの登録画面で容量、休止条件、カード登録の有無を接続直前に確認する。有料プランへの変更は自動で行わない。

## 秘密情報

TursoのデータベースURLと認証トークン、Googleの認証情報はGitHub、Obsidian、チャットへ保存しない。公開先の秘密変数として設定する。

想定する環境変数名:

- `TURSO_DATABASE_URL`
- `TURSO_AUTH_TOKEN`
- `GOOGLE_CLIENT_ID`
- `GOOGLE_CLIENT_SECRET`

値そのものは `.env` やGit管理対象のファイルへ書かない。

## 移行手順

1. 現在のSQLite版で全テストを維持する。（完了）
2. Turso用の保存処理を追加し、ローカルの一時libSQLデータベースで同じ認証・権限テストを実行する。（完了）
3. SQLiteからTursoへ一度だけ移すツールを作り、件数と内容のハッシュを照合する。（ツール実装済み、実接続未確認）
4. Turso側のバックアップまたはエクスポートと復元を確認する。
5. 公開先の秘密変数へURLとトークンを登録する。
6. 架空データで公開環境を確認してから、実際の社員を招待する。

移行完了まではSQLiteを削除しない。同時に両方へ書き込む期間を長く設けず、切替日時と移行元を記録する。

## Googleドライブ

Googleドライブにはファイル本体を置き、TursoにはGoogleのファイルID、表示名、金額、経費項目、処理状態、内容ハッシュを記録する。同じ領収書の二重登録はファイルIDと内容ハッシュで防ぐ。

管理者用のGoogle OAuth接続、接続状況、保存先フォルダ確認、接続解除の画面とAPIは実装済み。権限は `drive.file` に限定し、Googleトークンは認証付き暗号で保存する。接続解除時はGoogle側の許可取消を試み、ドライブ上の既存ファイルは削除しない。

最初は個人Googleアカウントで開始できる構造にし、法人用アカウントへ変更するときは、先にファイルを移して権限とIDを確認してから旧接続を解除する。

## 現在の状態

保存先の方針は決定した。アプリ本体はローカルとTursoで共通のlibSQL保存層へ変更済み。ローカルの認証・権限・同時更新テストは成功している。

`TURSO_DATABASE_URL` と `TURSO_AUTH_TOKEN` が設定されている場合はTursoを使用し、設定がなければ開発用のローカルファイルを使用する。既存SQLiteを移す `npm run migrate:turso` は、移行先に利用者または会社が存在すると上書きせず停止し、移行前バックアップ、表ごとの件数、内容ハッシュを確認する。

実際のTursoとGoogle OAuthの実接続は未完了。Google Cloud側のOAuth設定とユーザー所有の認証情報が必要。登録用の秘密値をチャットへ送る必要はない。
