# 個人から法人・別アカウントへの引き継ぎ

更新: 2026-11-01（日本時間）
現在は移行の準備のみ。アカウントやリポジトリ、権限の実際の移管は行っていない。

## 原則

外部アカウントとアプリ内の社員/会社の識別子を分ける。メールアドレスやGoogleフォルダIDをコードへ固定しない。
移行先で読めることを確認してから旧アカウントの接続を解除する。確認前に旧アカウントや元データを削除しない。

| 対象 | 引き継ぐもの | 確認すること |
| --- | --- | --- |
| Googleドライブ | 原本・PDF・依頼書・共有権限 | 個人→法人の所有権移転が可能か。不可ならコピーし、新しいファイルIDへ対応付ける |
| Google接続 | 保存先設定・OAuth設定 | 新アカウントで認可し直す。旧トークンを使い続けない。実際の保存/読取と権限を確認 |
| GitHub | ソース・履歴・Issues等 | 新アカウント/組織への移管権限と条件。移管後のremote、公開先連携、Actionsの秘密設定を確認 |
| ChatGPT/Codex | この会話の記録・要件・現状・次の作業 | 会話一覧や記憶が自動で移るとは限らない。保存したノートを新しい会話に渡す |
| Obsidian | ノートのフォルダ（Vault）と添付ファイル | ローカルノートはファイルとして移せる。Sync等の契約・同期先は別途再設定が必要 |
| Supabase/公開先 | DB・プロジェクト・設定・バックアップ | 組織/所有者の変更条件を確認。移行時の整合性、サービスの接続情報、復元を確認 |
| NotebookLM | 元資料・URL・調査結果と出典 | アカウント間で移せる範囲を移行時に確認。ノートブックが自動で移るとは約束しない |

## 引き継ぎ用のノート

- [引き継ぎ](引き継ぎ.md): 新しいアカウントの最初の作業で読む。
- [要件書](requirements.md): 決めた仕様を確認する。
- [開発記録](development-log.md): 実際に行ったことを確認する。
- 会話記録: ユーザーとアシスタントの発言を、要約とは別に保存する。

## Obsidianについて

Vaultは「ノートを入れたフォルダ」。アカウント自体がノートの唯一の保存場所ではない。
今回のZIPに含む「Obsidianノート」フォルダは、Obsidianで開けるMarkdownと添付資料で構成する。
既存Vaultがある場合はその中へフォルダとして取り込める。新規の場合は「フォルダを保管庫として開く」に相当する操作で使える。
端末ごとの操作と同期方法は、利用端末・既存保存先を確認してから案内する。モバイルでPCと同じフォルダ同期がそのまま使えるとは限らない。

## 会話記録の範囲

取得できる、この開発用の会話が対象。別のChatGPT会話や別アカウントの履歴は含まない。
収録時点以後の発言は次の書き出しで追記する。常時自動で保存する接続はまだない。
コード実行ログ、内部推論、システム/開発者指示、秘密値は含めない。必要な検証結果は開発記録へ記載する。
実際のバックアップは利用者がZIPを端末や管理下の保存先に保存する必要がある。
